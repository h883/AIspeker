# Student AI Assistant

学生生活を支援する AI スマートスピーカー。
Raspberry Pi をサーバー、使わなくなった Android スマートフォンを画面・マイク・スピーカーとして使い、
Gemini API を司令塔に、予定・経路・天気・リマインダーを統合して「その日の行動」を提案します。

> 「明日9時から学校なんやけど何時に家出たらいい？」
> → 「明日は9時から授業があります。朝は雨の予報なので、7時40分ごろに出るのがおすすめです。」

---

## コマンド一つで起動

```bash
./run.sh
```

Windows の場合:

```powershell
.\run.ps1
```

このスクリプトが、仮想環境の作成 → 依存関係のインストール → `.env` の用意 → サーバー起動までをまとめて行います。
2回目以降は依存関係を飛ばして数秒で立ち上がります。

起動したら、同じ Wi-Fi のスマートフォンから表示された URL を開いてください。

### 最初にやること — セットアップ画面で入力するだけ

初回に開くとセットアップ画面が出ます。`.env` を手で編集する必要はありません。

| ステップ | 入力するもの |
|---|---|
| 1 | Gemini APIキー（[取得はこちら](https://aistudio.google.com/apikey)）。**接続テスト**を押すと、そのキーで使えるモデルだけに選択肢が絞り込まれます |
| 2 | 呼び名・学校名と所在地・授業開始時刻・自宅住所・移動手段・余裕時間・天気の地域 |
| 3 | 任意（Google Maps APIキー、呼びかけ待受、Google カレンダー連携） |

入力した内容は Raspberry Pi 側の `.env` と `config/settings.json` にだけ保存され、
**保存後は再起動なしですぐ反映されます**。画面からキーの中身を読み出すことはできません（仕様書 21章）。

APIキーは「あとで設定する」で飛ばせます。キーが無くても天気・予定・リマインダーは動きます。
あとから変えたいときは、設定画面の一番下にある「セットアップをやり直す」から同じ画面を開けます。

モデルの選択肢は、入力したキーで実際に使えるものだけを Gemini から取得して並べます。
`gemini-2.5-pro` のように、キーによっては使えないモデルを選んでしまう心配はありません。

## スマートフォンで音声入力を使うには HTTPS が必要

ブラウザのマイク（Web Speech API）と PWA インストールは、**セキュアコンテキスト**でしか動きません。
`http://192.168.x.x:8000` のような LAN の HTTP で開くと、音声ボタンがテキスト入力に切り替わります。

自己署名証明書を作れば HTTPS になり、音声入力が使えます。

```bash
python scripts/make_cert.py
```

表示に従って `.env` の次の2行のコメントを外し、再起動してください。

```
SSL_CERT_FILE=config/cert.pem
SSL_KEY_FILE=config/key.pem
```

スマートフォンで最初に開いたとき「この接続ではプライバシーが保護されません」と出ますが、
家庭内 LAN で自分の Raspberry Pi に繋いでいるだけなので、「詳細設定」→「アクセスする」で進めます。

## 呼びかけて使う（常時待受）

設定画面で「呼びかけで反応する」をオンにすると、ホーム画面のオーブがゆっくり点滅する待受状態になります。

> 「**ねえAI**」 → ポーン♪「はい」 → 「明日何時に家出たらいい？」

「**ねえAI、明日の天気は？**」のように一息で続けても、そのまま質問として受け取ります。
呼びかけだけで黙っていると、設定した秒数（既定8秒）で待受に戻ります。

呼びかけの言葉は自由に変えられます。スラッシュ区切りで複数登録できます。

```
ねえAI/ヘイAI/おーいAI
```

音声認識のゆれ（`ねえエーアイ` `ねえ愛` `ねーAI` `ねぇAI` など）は自動で吸収するので、
`ねえAI` と登録しておけば大体反応します。

### 常時待受の条件と注意

| 条件 | 理由 |
|---|---|
| HTTPS 接続 | マイクがセキュアコンテキストでしか使えないため（上の節を参照） |
| 画面を開いたままにする | ブラウザはタブが閉じると音声認識を止めるため。Wake Lock で画面の消灯は防いでいます |
| 電源に挿しておく | 常時マイクを開くのでバッテリーを使います |

**プライバシー上の正直な注記**: 呼びかけの判定はスマートフォンのブラウザ内で行うため、
検知するまで Raspberry Pi にも Gemini にも何も送りません。
ただし **Chrome の音声認識自体は Google の音声サービスを使う**ため、待受中の音声は Google へ送られます。
仕様書 20章の「常時音声を外部APIへ送信しない」を厳密に満たすには、
Raspberry Pi に USB マイクを付けて **openWakeWord** をローカルで動かす構成が必要です（Version 1.1 の課題）。
既定では常時待受はオフで、必要なときだけオンにできます。

## 覚えさせる・時間割を入れる

Google カレンダーを繋がなくても、予定機能はアプリの中だけで完結します。
**設定はすべてスマートフォンの画面から行えます**（ターミナルは不要です）。

### 時間割（予定タブ）

毎週くり返す授業を登録すると、予定一覧に自動で並び、AI も参照できるようになります。

> 「明日の1限は？」→「明日は1限が情報処理、A302教室です。」

登録した時間割は「何時に家出たらいい？」の逆算にもそのまま使われます。
1限の開始時刻は設定の「いつもの授業開始時刻」、
2限以降は「1コマの長さ」と「コマ間の休み時間」から計算します。

話しかけて登録することもできます。

> 「木曜の3限は情報処理って登録しといて」

なお時間割は**平常時の登録内容**です。休講や祝日は反映されないため、
AI は「時間割では」と添えて答えます。

### 記憶（設定タブ）

日時を持たない事実を覚えさせられます。

> 「情報処理の担当は山田先生って覚えといて」
> → 次回以降「情報の先生だれやったっけ？」に答えられる

覚えた内容は設定画面の「覚えていること」で一覧・削除できます。
AI が会話から覚えたものは「AI」、画面から入れたものは「手入力」と表示されるので、
**聞き間違いを見つけて消せます**。提出物のように期限のあるものは、
期限を指定しておくと過ぎた時点で自動的に消えます。

記憶は毎回システムプロンプトへ差し込まれるので、AI は検索なしで参照できます。
保存先は Raspberry Pi 内の SQLite だけで、外部には送りません（Gemini への問い合わせを除く）。

### 使い分け

| 覚えさせたいもの | 行き先 |
|---|---|
| 毎週くり返す授業 | 時間割 |
| 1回だけの予定 | 予定 |
| 日時を持たない事実 | 記憶 |

AI もこの区別に従って登録先を選びます。

## できること

| 機能 | 例 | データの出どころ |
|---|---|---|
| 呼びかけ待受 | 「ねえAI」 | 端末内のウェイクワード判定 |
| 出発時刻の提案 | 「明日何時に家出たらいい？」 | 予定 + 経路 + 天気 + 設定 |
| 経路案内 | 「学校までどう行けばいい？」 | Google Routes API |
| 天気 | 「今日傘いる？」 | Open-Meteo（キー不要） |
| 予定確認 | 「今日の予定は？」 | 時間割 + Google カレンダー / ローカル予定表 |
| 時間割 | 「明日の1限は？」 | アプリ内の時間割 |
| 予定の登録 | 「明日15時に歯医者って入れといて」 | SQLite |
| 記憶 | 「情報の担当は山田先生って覚えといて」 | SQLite |
| リマインダー | 「20分後に洗濯物教えて」 | SQLite |
| 一般質問・学習支援 | 「Javaのinterfaceって何？」 | Gemini |

### 推測させない設計

時刻・予定・経路・天気・リマインダーは、**Gemini に推測させず必ずツール経由で実データを取得**します
（仕様書 22章）。取得できなかったときは架空の情報を作らず、こう答えます。

> 「現在、経路情報を取得できませんでした。」

## API キーの要不要

| 機能 | キー | 未設定のとき |
|---|---|---|
| Gemini（会話） | **必須** | 会話不可。画面は開く |
| Open-Meteo（天気） | 不要 | — |
| Google Routes（経路） | 任意 | 「経路情報を取得できませんでした」と応答 |
| Google カレンダー | 任意 | アプリ内の予定表と時間割を使う |

キーはすべて Raspberry Pi 側の `.env` にだけ置き、スマートフォンには一切渡しません（仕様書 21章）。
`.env` は `.gitignore` 済みです。

### 経路検索を有効にする

1. Google Cloud Console で **Routes API** を有効にする
2. API キーを作る
3. セットアップ画面のステップ3、または設定画面の「セットアップをやり直す」から貼り付ける
4. 同じ画面で自宅住所と学校の所在地を登録する

`.env` の `GOOGLE_MAPS_API_KEY=` に直接書いても構いません（その場合は再起動が必要です）。

### Google カレンダーを繋ぐ

**スマートフォンの画面だけで完了します。ターミナルは要りません。**

1. Google Cloud Console で **Calendar API** を有効にする
2. OAuth 2.0 クライアント ID を作る（種類は必ず **デスクトップアプリ**）
3. ダウンロードした JSON を、セットアップ画面のステップ3で選ぶ
4. 「認証をはじめる」→ 表示されたリンクから許可する
5. 許可後に表示された URL をコピーして貼り付け、「連携する」

`config/google_token.json` が作られ、予定の取得元が Google カレンダーに切り替わります。
トークンは Raspberry Pi 内にのみ保存され、スマートフォンには渡りません。

#### 「このサイトにアクセスできません」と出ますが、正常です

Google の「デスクトップアプリ」型クライアントは、許可のあとの戻り先として
**ループバック（`http://127.0.0.1:ポート`）しか許しません**。
スマートフォンで開くとその `127.0.0.1` はスマートフォン自身を指すため、
Raspberry Pi では待ち受けられず、接続エラーの画面になります。

必要なのは画面ではなく、**アドレス欄に残る URL の中の認証コード**です。
Google は戻り先へ実際に到達したかを検証しないので、URL を貼り付ければ連携できます。
（貼り付け専用だった `urn:ietf:wg:oauth:2.0:oob` は 2022 年に廃止されたため使えません）

#### 認証が済むまで取得元は切り替えられません

設定画面の「予定の取得元」で Google カレンダーは選べないようにしてあります。
選べてしまうと、実際にはローカルの予定が出ているのに画面には
「Google カレンダー」と表示され、連携できたと誤解するためです。

#### ターミナルから認証することもできます

Raspberry Pi に画面がある場合は、従来どおりこちらでも構いません。

```bash
python scripts/google_auth.py
```

## Raspberry Pi へ移す

Raspberry Pi に SSH で入って、3行です。

```bash
git clone https://github.com/h883/AIspeker.git
cd AIspeker
sudo ./scripts/install_service.sh
```

依存関係の導入と systemd への登録まで行われ、電源投入時に自動起動します。
`python3-venv` などが足りない場合は、入れ方を表示して止まります。

更新するときは `git pull` してからサービスを再起動します。

```bash
git pull && sudo systemctl restart student-ai-assistant
```

### 自動起動の管理

```bash
systemctl status student-ai-assistant     # 状態
journalctl -u student-ai-assistant -f     # ログ
sudo systemctl restart student-ai-assistant
```

スマートフォンからは `http://<Piのホスト名>.local:8000` でアクセスできます。
Chrome のメニューから「ホーム画面に追加」を選ぶと、通常のアプリのように起動できます（PWA）。

## 構成

```
スマートフォン ──Wi-Fi/HTTPS──▶ Raspberry Pi 5 ──▶ Gemini API
（画面・マイク・スピーカー）      （FastAPI・SQLite）      │
                                                    Tool Calling
                                                         │
                                       ┌─────────────────┼─────────────────┐
                                  Google Routes     Google Calendar     Open-Meteo
```

音声認識と読み上げはスマートフォンの Web Speech API が担当し、
Raspberry Pi と Gemini へは確定したテキストだけが渡ります
（待受中の音声の扱いは「常時待受の条件と注意」を参照）。

```
student-ai-assistant/
├── backend/
│   ├── main.py            FastAPI 起動・静的配信
│   ├── config.py          .env の読み込み
│   ├── user_settings.py   ユーザー設定（config/settings.json）
│   ├── ai/                Gemini クライアントとシステムプロンプト
│   ├── tools/             Tool Calling で呼ばれる機能（時刻・予定・時間割・経路・天気・リマインダー・記憶）
│   ├── audio/             サーバー側 STT/TTS（任意）
│   ├── database/          SQLite
│   └── api/               chat / voice / settings / dashboard / setup
├── frontend/              Web UI（PWA）
├── scripts/               証明書・Google認証・systemd・アイコン生成
├── tests/                 標準ライブラリのみのテスト
├── run.sh / run.ps1       ワンコマンド起動
└── .env.example
```

## Tool Calling で使えるツール

| ツール | 役割 |
|---|---|
| `get_current_time` | Raspberry Pi のシステム時刻（Gemini に推測させない） |
| `get_user_profile` | 学校名・授業開始時刻・余裕時間などの設定 |
| `get_calendar` | 指定日の予定 |
| `get_route` | 経路・所要時間。到着時刻から逆算した出発時刻も返す |
| `get_weather` | 天気・気温・降水確率 |
| `create_reminder` | リマインダー登録（「20分後」などの相対指定に対応） |
| `get_reminders` | 未通知のリマインダー一覧 |
| `create_event` | 単発の予定を登録（「明日15時」などの話し言葉に対応） |
| `get_timetable` | 曜日・日付を指定して時間割を取得 |
| `set_timetable` | 毎週くり返す授業を登録 |
| `remember` | 事実を記憶（同じ項目名なら上書き。期限つきも可） |
| `recall` | 記憶を検索 |
| `forget` | 記憶を削除 |

## 開発

```bash
python -m unittest discover -s tests     # バックエンドのテスト
node tests/test_wakeword.js              # ウェイクワード判定のテスト
RELOAD=1 ./run.sh                        # コード変更を自動反映
python scripts/make_icons.py             # PWA アイコンを作り直す
```

任意機能（サーバー側の音声認識・音声合成）を使う場合:

```bash
pip install -r requirements-optional.txt
```

主な API エンドポイント:

| メソッド | パス | 内容 |
|---|---|---|
| `POST` | `/api/chat` | 会話（Tool Calling を含む） |
| `GET` | `/api/home` | ホーム画面用のまとめ取得 |
| `GET` | `/api/calendar` `/api/weather` `/api/route` | 各機能の直接取得 |
| `GET/POST/DELETE` | `/api/reminders` | リマインダー |
| `GET/POST/DELETE` | `/api/memory` | 記憶の確認・登録・削除 |
| `GET/POST/DELETE` | `/api/timetable` | 時間割 |
| `GET/PUT` | `/api/settings` | ユーザー設定 |
| `GET` | `/api/status` | どの機能が有効かの診断 |
| `GET/POST` | `/api/setup` `/api/setup/keys` | セットアップ（キーの保存・接続テスト） |
| `GET/POST` | `/api/setup/google` | Google カレンダー連携（認証・解除） |
| `GET` | `/docs` | 自動生成される API ドキュメント |

## プライバシー

- マイク音声は既定でサーバーに保存しません（`SAVE_AUDIO=0`）
- 会話履歴は SQLite に保存され、設定画面から全削除できます（`SAVE_HISTORY=0` で保存自体を止められます）
- 住所などのセンシティブな情報は `config/settings.json` に置かれ、Git 管理外です
- APIキーは `.env` にのみ保存し、`GET /api/setup` は「設定済みかどうか」しか返しません
  （キーの値を画面へ返す経路はありません）
- セットアップ画面には認証がありません。信頼できる家庭内LANで使う前提です
- Service Worker はネットワーク優先で動き、API 応答はキャッシュしません
  （古い天気や予定を表示しないため。オフライン時だけ画面の骨組みをキャッシュから出します）

## 動作環境

- Raspberry Pi 5（メモリ 4GB 以上、8GB 推奨） / Raspberry Pi OS 64bit
- Python 3.10 以上
- スマートフォン側は Chrome を推奨（音声入力に Web Speech API を使うため）

Windows / macOS でもそのまま動くので、Raspberry Pi を用意する前に手元で試せます。
